# The Golem MCP server

One server per agent, hosted inside the Golem process over Streamable HTTP at `http://127.0.0.1:<port>/agents/<name>/mcp`, protected by a per-agent bearer token. It is passed to the mind in `session/new` (see ACP.md). A stdio shim (`golem mcp-stdio --agent <name>`) proxies to the same endpoint for agents that only support stdio MCP servers.

Tools are grouped and named with a short prefix so they sort together in the agent's tool list. Results are compact text unless stated; `see` returns image content. Every action tool returns `{ ok, took_ms, ...detail }` and, on failure, `{ ok: false, kind, message }` with the same error kinds as Shem.

| `container` |  | Contents of the container you have open (or villager trades). |
| `craftable` |  | What you can craft right now with what you carry. |
| `recipe` | item | Recipes that produce an item: ingredients, counts, whether a crafting table is needed. |
| `players` |  | Who is online. |
| `chat_history` | limit | Recent chat lines you've seen. |
| `target` |  | What your crosshair is on. |

## Prompts

None registered yet. The orientation lives in the workspace `AGENTS.md` (Claude reads it as `CLAUDE.md`, Gemini as `GEMINI.md`), regenerated by Golem at session start, and the first inbox item of a session says "you just woke up".

## Design notes

- Tool descriptions are the agent's documentation. They come from one registry (`src/mcp/tools.ts`) that also feeds the workspace orientation doc and this page (`npm run gen:tools`), so the three never drift.
- Every action tool is a primitive of the same name. The mind can start with one-shot tools and graduate to scripts when it notices it's repeating itself.
- Results are text, not JSON dumps, wherever a human-readable line does the job. `see` and `map` return image content as well.
- Tool errors come back as `<kind>: <message>` with `isError`, using the same kinds as the primitives (`unreachable`, `missing_item`, `preempted`, ...).
