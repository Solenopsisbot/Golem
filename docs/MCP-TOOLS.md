# The Golem MCP server

One server per agent, hosted inside the Golem process over Streamable HTTP at `http://127.0.0.1:<port>/agents/<name>/mcp`, protected by a per-agent bearer token. It is passed to the mind in `session/new` (see ACP.md). A stdio shim (`golem mcp-stdio --agent <name>`) proxies to the same endpoint for agents that only support stdio MCP servers.

Tools are grouped and named with a short prefix so they sort together in the agent's tool list. Results are compact text unless stated; `see` returns image content. Every action tool returns `{ ok, took_ms, ...detail }` and, on failure, `{ ok: false, kind, message }` with the same error kinds as Shem.

## Registered tools (35, generated by scripts/gen-tool-docs.ts)

### Perception

| Tool | Args | What it does |
|---|---|---|
| `status` |  | Where you are, health, food, time, held item, current activity, reflex states. |
| `look_around` | radius | Structured summary of your surroundings: threats, players, mobs, drops, nearby useful blocks, what you stand on, inventory line. |
| `see` | x, y, z, yaw, pitch, width, height | Take a picture from your eyes (or a given camera position/angle). Returns a PNG. Use when layout or looks matter; look_around is cheaper and exact. |
| `map` | radius | Top-down map of the area around you as a PNG. |
| `find_blocks` | kinds, radius, max | Nearest blocks of the given kinds (e.g. ["oak_log","iron_ore"]), nearest first, with coordinates. |
| `find_entities` | kinds, radius, hostile_only | Nearby entities with ids, positions, distances and whether they're hostile. Filter by kinds ("zombie", "item", "player"). |
| `block_at` | x, y, z | What block is at a position. |
| `inventory` |  | Your inventory, armor, held item. |
| `players` |  | Who is online. |

### Movement

| Tool | Args | What it does |
|---|---|---|
| `goto` | x, y, z, reach, timeout_s | Walk to a block position (Baritone pathing). Blocks until you arrive within `reach` blocks or fail. Use reach 2-3 for solid targets. |
| `stop` |  | Stop moving, mining, pathing and item use. |

### Actions

| Tool | Args | What it does |
|---|---|---|
| `mine` | x, y, z | Break one block at a position (walks there, picks the best tool, collects the drop). |
| `use_on` | x, y, z, entity_id | Right-click a block (door, lever, bed, chest...) or an entity id with what you hold. |
| `equip` | item | Equip armor, a shield, or move a tool to hand. |
| `eat` | item | Eat a named food, or the best food you carry. |
| `craft` | item, count | Craft an item (uses a crafting table if one is open or needed and nearby). |
| `dm` | agent, text | Send a message to another golem in this fleet (see `agents`). Conversations are capped per pair, so say what matters and don't chat for the sake of it. |
| `agents` |  | The other golems in this fleet and what they're doing. |
| `plan_next` | reason | Ask for your next turn to run on the stronger planning model. Use before a big decision (where to build, a long expedition, what to do after repeated failures). Say why in one line, then end your turn right after calling this. |

### Comms

| Tool | Args | What it does |
|---|---|---|
| `say` | text | Say one line in game chat. Short. Rate-limited. |
| `inbox` |  | Anything that arrived since your turn started (chat, damage, reflexes). |

|---|---|---|

| `reflexes` |  | List reflexes and whether they're on. |

| `goal_set` | text | Set your standing goal. Golem will wake you periodically to continue it when nothing else is happening. |
| `goal_clear` |  | Clear the standing goal. |
| `met` |  | Stop everything immediately: movement, mining, pathing, reflex actions. |

### Scripts (Shem)

| Tool | Args | What it does |
|---|---|---|
| `shem_check` | path, source | Diagnostics for a script file without running it (path under your workspace, or lib/<name>). You don't need this before shem_run: shem_run checks first and refuses to run a file with errors, returning the same diagnostics. |
| `shem_run` | path, script, params, priority, interrupt, background, timeout_s | Check and run a script from a file in one call. `path` is the file (shem/mine.shem, or lib/wood for the standard library); `script` is the script name inside it (required when the file has several). Runs the checker first and returns its diagnostics instead of running if there are errors. With background=true Golem tells you in your inbox when the run ends; don't poll it. |
| `shem_eval` | save, code, params, timeout_s, background | Run a Shem snippet (statements, or a whole file with script declarations) in one call. Pass `save` (e.g. shem/harvest.shem) to also keep it as a script: the snippet is checked, written to that file, and the saved file is run, so a new script costs one call instead of write + check + run. Bare statements are saved wrapped as `script main()`. Put say/dm/block_at/inventory checks inside the snippet rather than making separate calls. |
| `shem_status` | run | Status and trace tail of a run. Rarely needed: foreground runs return their result, background runs report into your inbox when they end. |
| `shem_wait` | run, timeout_s | Wait for a background run to end (bounded). Prefer letting it report into your inbox and doing something else meanwhile. |
| `shem_cancel` | run | Cancel a run, or every active run when omitted. |
| `shem_runs` |  | Active and recent runs. |
| `shem_doc` | name | Documentation for a Shem function, getter, event, or library script by name. |

## Resources

## Prompts

None registered yet. The orientation lives in the workspace `AGENTS.md` (Claude reads it as `CLAUDE.md`, Gemini as `GEMINI.md`), regenerated by Golem at session start, and the first inbox item of a session says "you just woke up".

## Design notes

- Tool descriptions are the agent's documentation. They come from one registry (`src/mcp/tools.ts`) that also feeds the workspace orientation doc and this page (`npm run gen:tools`), so the three never drift.
- Every action tool is a primitive of the same name. The mind can start with one-shot tools and graduate to scripts when it notices it's repeating itself.
- Results are text, not JSON dumps, wherever a human-readable line does the job. `see` and `map` return image content as well.
- Tool errors come back as `<kind>: <message>` with `isError`, using the same kinds as the primitives (`unreachable`, `missing_item`, `preempted`, ...).
